# October 17 coordinator and focused component evaluations

## Boundary and acceptance

The Sessions SQLite event store remains the read-only observation and export record. The new `session_coordinator.py` owns a separate durable, ordered queue and only dispatches an explicitly authorized, fixed read-only GLM review adapter through a loopback tunnel. It records the request ID and `submitted` transition before HTTP, then the response, usage and finish reason. `stop` plus nonempty content becomes `completed`; a human must separately record source/test evidence for `independently_verified`. `length` becomes `failed`; a transport exception becomes `unresolved`. No arbitrary command or model-generated instruction can execute.

The worker's SQLite `BEGIN IMMEDIATE` transaction serializes claims; an owner heartbeat renews during a request. New ownership turns submitted or acknowledged work into unresolved, never automatic replay. An explicit manual retry requires a failed request with no stored response, concrete no-execution evidence and fewer than two attempts. Pause, permanent stop, dependency verification and the fixed rental ceiling gate dispatch. A paused in-flight response can still be stored. The worker does not offer exactly-once remote execution, authenticate a same-user database, or replace Keel authorization. The review adapter is fixed to `127.0.0.1:18001`, served alias `glm-5.3-flash` for pinned `wtdcode/GLM-5.3-Flash-AWQ-W4A16`; both `reasoning_effort` and `chat_template_kwargs.reasoning_effort` are `low`.

October 17 continuation: the prior `serve` process exited by its own ten-minute idle timer when both queued drafts were blocked by failed predecessors. Its control mode remained `running` and its old owner heartbeat stayed in SQLite; that mode only authorized dispatch and did not prove worker liveness. The MacBook worker now has a separate PID, token and heartbeat record, exposed in the read-only export and Sessions view. An absent or stale worker with running control is an explicit alert. The idle timer was removed; the worker waits through idle periods and pause until stopped or budget gated. A macOS LaunchAgent supervises the worker with `KeepAlive` on unsuccessful exit and `RunAtLoad`; this is automatic process recovery while the user launchd domain is available, but uncertain remote submissions still require evidence-based operator reconciliation. A live idle worker was killed with SIGKILL; launchd restarted it with a new PID and token. The worker does not shut down the provider.

Stale ownership is reconciled even if dispatch is paused or budget gated, without replay. An inaccessible live PID fails closed when checking single-worker ownership. Tests cover unexpected exit, stale status, safe recovery with an ambiguous submission, paused/budget-gated reconciliation, and denied PID probe. The two original HTTP 400 requests were model-alias errors, and the broad V2 response ended `length`; their dependents remain blocked. A completed GPU critique was independently rejected with recorded evidence because its supplied source was cut mid-line and its alleged utilization-to-completion path did not exist. Two fresh focused requests completed with `stop`: a worker recovery review identified the stale reconciliation and PID-probe defects, both fixed and tested; a corrected GPU boundary review found no utilization-to-verification path, checked against current source. Human review separately accepted both focused responses. Provider billing remains distinct from estimated fixed rental spend.

A broader supervision critique then ended `length` and remains failed, despite a useful hypothesis in its partial response. Independently inspecting `_worker_active` found that `PermissionError` bypassed the heartbeat age; the helper now treats an inaccessible PID as potentially live for at most the 30-second lease. A focused test proves fresh denial blocks takeover and stale denial permits recovery. The truncated review was neither accepted nor counted as completed work.

Two shorter follow-up GLM reviews of the updated ownership and paused-recovery paths returned `stop` and were separately checked against source and the focused tests. Both found no current bypass. No queued task was unlocked through either failed predecessor; the new requests were independently authorized contracts. The worker stays resident and polls every five seconds for further eligible work, while launchd supervises an unexpected exit. On budget gate it exits successfully, and automatic provider shutdown remains disabled.

Acceptance: 44 focused tests passed, including two task restart preservation, budget refusal after restart, uncertain submission without replay even with a reused owner ID, truncation, pause, manual retry limit, telemetry outage, redirect refusal, and denied/unavailable policy decisions. Live MacBook run persisted two initial HTTP alias errors, reconciled them as failed, then a truncated review (`length`) and a complete review (`stop`). The complete review was independently adjudicated against code and tests. GLM's claim that `length` was accepted is false: `run_one` marks it failed. Its settings-injection claim is blocked by exact settings validation. A subsequent telemetry contract review completed; its synchronous-export concern prompted bounded asynchronous metadata emission. Three further GLM reviews completed: the recovery critique prompted a restart budget test, the OPA critique identified the real policy-hash/server-binding gap, and the GPU critique remained unaccepted because the supplied excerpt ended mid-file and its completion claim conflated process state with verified outcome. A final three-review batch found a real HTTP redirect escape in the default Python opener and a stale same-owner recovery gap; both were fixed and tested. In-flight responses after pause are recorded as actual observations, not new dispatches or verified work. Existing Sessions and report-action tests passed alongside the new tests.

## Ordered project decisions

| [LangGraph 1.2.13](https://github.com/langchain-ai/langgraph/releases) | MIT; `langchain-core`, checkpoint, SDK, prebuilt, Pydantic and xxhash in the [package manifest](https://github.com/langchain-ai/langgraph/blob/main/libs/langgraph/pyproject.toml). Checkpoints persist graph state; [interrupt/resume](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/interrupts.mdx) can replay a node and require separate side-effect reconciliation. Its migration and checkpoint owner would duplicate our SQLite authority. No hosted LangSmith needed. | Defer adapter; existing transactional queue is smaller for a fixed worker. |
| [OpenLIT Python SDK 1.45.0](https://github.com/openlit/openlit/blob/main/sdk/python/README.md) | Apache 2.0. The inspected wheel lists OpenAI, Anthropic, boto3 and many OTel instrumentors; isolated install measured **141 MiB**. SDK default content capture is true; the experiment set it false and disabled automatic instrumentors. A synthetic request emitted a metadata-only OTLP span to a local HTTP sink with session/task/request/model, monotonic latency, finish reason and token counts; no secret prompt/response markers appeared. Synthetic `length` and telemetry exception tests leave the task failed or complete according to the model result, never verified. Current [OSS pricing](https://www.openlit.io/pricing) says free self-hosting; [Enterprise](https://www.openlit.io/enterprise) lists RBAC, audit, alerts, scoped keys and GPU cost features. | Defer runtime dependency and dashboard; optional bounded metadata callback meets the narrow need at lower footprint. |
