## Implemented provenance improvement

The experimental OPA `DecisionLedger` now retains optional `session_id`, `task_id` and `request_id` from a supplied decision document. Existing rows migrate additively and keep null links. This makes a supplied policy decision easier to correlate with a workflow, but it cannot fabricate missing IDs or authenticate the caller. The actual executor still records the decision before action and refuses missing Keel approval, deny, unavailable evaluator, or ledger failure. No real OPA daemon was deployed and no OpenClaw action contract was changed. The broader workflow already links saved task IDs to approvals, execution attempts and verification in its own records; telemetry alone never establishes an enforced or verified result.

The sampled bundled pilot `.app` on the Mac occupies 63,556 KiB. It contains the Swift/AppKit shell, a PyInstaller-frozen Python backend, templates/static resources, icon, local configuration, public activation key and a `pilot-build.json` with Python 3.14.7, source digest/commit and ad-hoc signing state. No model weights or private issuer key are built by `apps/desktop/package.py`. The sampled bundle's source commit is older than this review checkpoint, so it is inventory evidence rather than proof the latest source is installed. The source has a separate dependency lock/build manifest from pilot acceptance, but the sampled app has no embedded SPDX/CycloneDX SBOM or consolidated notices. The signed release manifest binds an artifact digest, platform, architecture, compatibility and channel; an SBOM can be produced beside and associated with that digest, without representing Apple Developer ID signing or notarization. Model weights live on the rental, outside the app: capture their exact repo, revision and inherited base-model terms in the deployment inventory before redistribution; current card metadata for the AWQ repository did not establish a complete license review.

No new service or default runtime dependency was added. License choices above are repository-level observations; transitive license checks are still required before any component is bundled into closed-source distribution.
